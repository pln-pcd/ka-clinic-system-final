# Study mode & ethics

These rules come from the thesis ethics approval and apply to the whole system during the study. They take precedence over any earlier feature behaviour.

## Chatbot (KAI)

**Allowed:** general clinic information (services by name, location, phone, email), office hours (walk-in Monday–Friday, appointments Saturday–Sunday, 8 AM–5 PM, lunch 12–1), appointment procedures (how to book or cancel in the app), and app navigation.

**Not allowed:** diagnosis, treatment, wound care, rabies-risk assessment, vaccine recommendations, PEP schedules or regimens, medication advice, emergency advice, prices, and the patient's own dates, dose counts or treatment status.

How it is enforced:

| Layer | Where |
|---|---|
| Deterministic classifier, run **before** any AI call (English, Filipino/Tagalog, common Bikol). Anything it cannot place gets the blocked reply. | `api/_lib/chatbotRules.js` (server), `patient-app/services/chatbotRules.ts` (on-device copy) |
| Blocked topics → one fixed neutral reply: "I can't help with medical questions. Please contact K&A Clinic or a licensed healthcare professional." + clinic phone/email + "Talk to clinic staff" (app). | same |
| Personal schedule questions ("When is my next dose?") → navigation only: "You can see your vaccination schedule on the Home screen under your vaccination card." + a button to the card. No dates, sessions or counts. | same |
| The AI system prompt restates the same limits, and the AI's reply is checked again; medical content is replaced by the blocked reply. | `api/chatbot.js` |
| Visible disclaimer banner at the top of the chat and a short line under the input. | `patient-app/app/(tabs)/chat.tsx`, `ka-clinic-admin/src/components/landing/Chatbot.jsx` |

Test it: `node scripts/test-chatbot-scope.mjs` (sample prompts with expected categories, run against the server rules and the app copy; also checks that no fixed reply carries medical text).

During the study the chatbot is used with **test prompts only**, never by real patients.

## Incident map

- Shows **only simulated, non-identifiable test records** (`isSimulated: true`). Generated by `ka-clinic-admin/src/lib/simulatedIncidents.js`: random coordinates inside a box around the town, a generic label ("Simulated incident #12 · Dog bite · Category II · Sep 2026"), no address, barangay, zone, patient or MRN.
- No addresses, barangay filters, barangay counts or summaries, heatmaps or coordinates are shown. A banner says "Simulated test data for demonstration only — not real cases", and the map area carries a "SIMULATED DATA" watermark.
- Only signed-in, active admins can open it (dashboard route + `firestore.rules`). `firestore.rules` returns only `isSimulated == true` incidents and accepts only simulated pins with the simulated fields. Patients and the public cannot read incidents; the landing page and the patient app do not show the map.
- Seed simulated pins: `node --env-file=.env scripts/seed-simulated-incidents.mjs [--count 30]`. The sample/demo seed scripts write simulated pins too. Older non-simulated incident docs stay hidden; `--purge-nonsimulated --yes` deletes them permanently.
- `scripts/data-migrations.mjs fix-incidents` (which wrote real addresses) is disabled.

## Flags

| Variable | Default | Effect |
|---|---|---|
| `VITE_CHATBOT_STUDY_MODE` (admin/website build) | on unless `false` | Website chatbot shows "Test environment — do not enter real patient information." |
| `EXPO_PUBLIC_CHATBOT_STUDY_MODE` (patient app build) | on unless `false` | Same notice in the app chat. |
| `VITE_MAP_STUDY_MODE` (admin build) | on unless `false` | "Pin Incident Map" is hidden on patient records and the pin action refuses, so real patient data never becomes map data. |

Turning `VITE_MAP_STUDY_MODE` off after the study is **not enough** to pin real records again: `firestore.rules` also accepts only simulated incidents, and that rule has to be changed and redeployed deliberately.

## Data

- The study environment uses **seed data only** (`isSeedData` / `isDemo` docs from the scripts in `scripts/`). Check with `node --env-file=.env scripts/verify-sample-data.mjs`, which also fails if any incident is not simulated, carries an identifying field, or is linked from a patient record.
- Reports (clinic registry, patient record, inventory) contain no incident locations.
